招聘帖子增量抓取，能否做到不重复？

这个原型验证的状态模型是：TikHub 每次返回一个可能与历史重叠的最近内容窗口，我们是否能保证帖子只入库一次，并看清哪些重复费用可以减少、哪些无法消除。

当前判断：稳定帖子 ID 可以保证不重复入库；TikHub 按成功请求计费，无法保证每次响应只含新帖，所以“绝不为重复结果付费”不能由客户端完全实现。
